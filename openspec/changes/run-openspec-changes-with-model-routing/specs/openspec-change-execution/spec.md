## Purpose

OpenSpecを使う開発対象で、次に実行すべきchangeを選び、その作業ディレクトリでそのまま実行できることを確かめてから、apply・独立レビュー・最終確認を経て同期・アーカイブまで進める。

## ADDED Requirements

### Requirement: 次に実行するchangeを選定する
実行器は、OpenSpecのchangeを対象とするワークフローの開始時に、開発対象の未アーカイブのchangeから実行するchangeを1件選ばなければならない（MUST）。クライアントがchangeを指定した場合はそれを使う。候補が複数ある場合は、実行前レビューの工程で依存関係・進捗・内容から選び、選定の根拠を記録する。判断できない場合は推測せず質問する。

#### Scenario: changeを指定して開始する
- **WHEN** クライアントが存在する未アーカイブのchangeを指定して開始する
- **THEN** そのchangeを対象として記録し、選定の判断を省略して実行前レビューを行う

#### Scenario: 候補が複数ある
- **WHEN** changeの指定がなく、未完了のタスクを持つchangeが複数ある
- **THEN** 実行前レビューの工程が1件を選び、選定の根拠を記録する

#### Scenario: 実行できるchangeがない
- **WHEN** 未アーカイブのchangeがない、または指定したchangeが存在しない
- **THEN** モデルを呼ばずに開始を拒否し、理由を返す

### Requirement: 実行前にchangeが実行可能か確認する
実行器は、apply前に1つのコンテキストでchangeを選定・レビューし、その作業ディレクトリでそのまま実行できるかを、現在のコード・既存仕様・他のchange・実行環境の前提と照合して判断しなければならない（MUST）。必要な調査と技術的な決定は自ら行い、クライアントの業務判断が必要な場合だけ質問する。判断の根拠と、applyの単位となる順序付きのタスク群と受け入れ条件を記録する。

#### Scenario: そのまま実行できる
- **WHEN** changeの内容が作業ディレクトリの現状と矛盾しない
- **THEN** changeを変更せず、根拠とタスク群を記録してapplyへ進む

#### Scenario: クライアントの判断が必要
- **WHEN** changeの実行に、クライアントでなければ決められない不明点がある
- **THEN** waitingで停止し、ルートセッションのチャットに質問する

### Requirement: 必要な場合だけchangeを更新する
実行前レビューの工程は、changeが現状と合わない場合に限り、対象changeのディレクトリ内のファイルだけを更新しなければならない（MUST）。更新後のchangeはOpenSpecの検証に合格しなければならない。開発対象のコードや他のchangeを変更してはならない。更新した内容と理由は、クライアントに報告できる形で記録する。

#### Scenario: changeを更新する
- **WHEN** 実行前レビューがchangeの設計やタスクの修正を必要と判断する
- **THEN** 対象changeのディレクトリ内だけを更新し、検証に合格した後で更新の要約を記録してapplyへ進む

#### Scenario: 範囲外へ書き込もうとする
- **WHEN** 実行前レビューの工程が対象changeのディレクトリ外を変更しようとする
- **THEN** その変更は許可されず、完了として扱われない

#### Scenario: 更新後の検証に失敗する
- **WHEN** 更新したchangeがOpenSpecの検証に合格しない
- **THEN** applyへ進まず、実行前レビューを完了として扱わない

### Requirement: タスク群ごとにapplyと独立レビューを行う
実行器は、実行前レビューが定めたタスク群ごとに、applyとその独立レビューを別々のコンテキストで実行しなければならない（MUST）。applyは該当タスク群だけを実装し、changeのタスクの完了状態を更新する。独立レビューに合格したタスク群だけを完了扱いにする。差し戻しは実行前レビューで未完了分を再定義し、既存の手戻り上限に従う。

#### Scenario: 1つのタスク群を完了する
- **WHEN** applyが1つのタスク群を実装し、独立レビューが受け入れ条件を満たすと判断する
- **THEN** そのタスク群を完了とし、次のタスク群または最終確認へ進む

#### Scenario: レビューで差し戻す
- **WHEN** 独立レビューが修正を要求する
- **THEN** 実行前レビューの工程で未完了分を再定義し、完了済みのタスク群とその成果・証拠を保持する

### Requirement: 最終確認を常に行う
実行器は、すべてのタスク群が独立レビューに合格した後、タスク群の数にかかわらず、change全体の最終確認を新規コンテキストで実行しなければならない（MUST）。最終確認はproposal・仕様の差分・全タスクの完了状態と実装・検証結果を照合し、タスク群にまたがる不整合と無関係な変更がないことを確認する。不足があれば差し戻す。

#### Scenario: タスク群が1つだけ
- **WHEN** 1つのタスク群が独立レビューに合格する
- **THEN** 最終確認を省略せずに実行し、合格した後でcompletedとする

#### Scenario: change全体に不足がある
- **WHEN** 最終確認が仕様の差分を満たさない点や未完了のタスクを見つける
- **THEN** 差し戻し、completedにしない

### Requirement: 完了後にchangeを同期・アーカイブする
ルートセッションは、changeのワークフローがcompletedになった後、実行器を通じてchangeの仕様の差分を開発対象の仕様へ同期し、changeをアーカイブしなければならない（MUST）。結果はイベントに記録し、チャットで報告する。失敗した場合はcompletedの記録を変えず、エラーを提示して停止する。コミット・push・公開は行わない。

#### Scenario: アーカイブに成功する
- **WHEN** completedのchangeワークフローでアーカイブを実行する
- **THEN** 仕様の差分が同期され、changeがアーカイブへ移り、その結果が記録・報告される

#### Scenario: 未完了のワークフローでアーカイブする
- **WHEN** completedでないワークフローでアーカイブを要求する
- **THEN** 実行を拒否し、開発対象を変更しない

#### Scenario: アーカイブに失敗する
- **WHEN** OpenSpecのアーカイブがエラーで終了する
- **THEN** エラーを記録・提示し、ワークフローのcompletedの状態と成果を保持する
