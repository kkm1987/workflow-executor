## Why

クライアントはOpenSpecで開発しており、最初に任せたいのは「次のchangeを選び、その作業ディレクトリでそのまま実行できるか確かめ、必要ならchangeを更新してからapplyする」流れである。現在の実行器は自由記述の要求を計画から始め、全工程を同じCodex設定で新規コンテキストとして実行するため、工程に応じたモデル・推論レベルの使い分け、Claudeによる実行前レビュー、利用枠不足の事前検出、質問への回答後の作業継続ができない。

## What Changes

- OpenSpecのchangeを対象とするワークフローを追加する。工程は「選定＋実行前レビュー → apply（タスク群ごと） → 独立レビュー → 最終確認」とし、完了後にルートセッションがchangeを同期・アーカイブする。
- 実行前レビューでは、未完了のchangeから次に実行するものを選び、作業ディレクトリでそのまま実行できるか調査・判断し、必要ならchangeを更新する。書き込みは対象changeのディレクトリに限る。
- 工程ごとに実行CLI（CodexまたはClaude）・モデル・推論レベルを指定できるようにする。既定値は設定ファイルで変更でき、ルートセッションの会話で指定した値をワークフローごとに保存して優先する。
- 既定の割り当て：実行前レビューは`claude-opus-5-5`/medium、applyは`gpt-6.1-sol`/low、独立レビューと最終確認は`gpt-6-luna`/high。ルートセッションはクライアントのCodex設定（想定：`gpt-6-luna`/low）で動き、仲介に徹する。
- **BREAKING** 質問への回答後は、質問した工程の同じセッションを再開する。モデル・CLIの変更、再開の失敗、失敗からのretryでは新規コンテキストで再実行する。Codexの実行は`--ephemeral`を使わなくなる。
- 工程の開始前に利用枠を確認し、工程ごとの固定値を下回る場合はモデルを呼ばずに停止して、ルートセッションが別モデルの使用を提案する。実行中に上限へ達した場合も別の失敗種別として扱う。モデルは自動で切り替えない。
- Codex実行ファイルは、デスクトップアプリ同梱の最新版、`PATH`上の`codex`の順に探す。

## Capabilities

### New Capabilities

- `openspec-change-execution`: changeの選定、実行前レビューとchange更新、タスク群ごとのapplyと独立レビュー、最終確認、完了後の同期・アーカイブ。

### Modified Capabilities

- `workflow-runtime`: 工程ごとの実行CLI・モデル・推論レベルの指定、利用枠の事前確認と上限時の扱い、質問後のセッション再開、Codex実行ファイルの探索、実行前確認の対象CLI。
- `workflow-observability`: 試行ごとに使用したCLI・モデル・推論レベル・セッションと、試行前後の利用枠を記録する。

## Impact

- `src/executor.js`、`src/workflow.js`、`src/preflight.js`、`src/metrics.js`、`src/cli.js`、`src/result.schema.json`、新しい設定ファイル、skill、テスト、README・MVP。
- Claude Code CLI（`claude -p`）を工程実行に使うため、Claude Codeのログインが必要になる。Codexのセッション履歴がCodexの保存先に残るようになる（開発対象には保存しない）。
- 既存の自由記述要求のワークフロー（plan開始）は維持する。保存済みワークフローは既定の割り当てで再開できる。
- 利用枠の固定値は根拠となる計測がない初期値であり、試行ごとの記録から見直す。並列実行、常駐実行、モデルの自動切り替え、コミット・PR作成は追加しない。

基準となる要求は[要求仕様](../../../docs/SRS.md)と[MVP](../../../docs/MVP.md)。
