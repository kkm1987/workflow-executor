## Context

動機はproposal.mdを参照。現状はstdoutを直接ファイルへ渡し、10秒ごとのsaveで状態だけを更新する。Codexのattempt-0002では作業報告2件と最終JSON、コマンドの開始・終了を確認できた。一方で途中報告がない試行もある。Claudeは単一JSONで最終結果のみを取得している。ローカルCLIのhelpでstream-json対応を確認したが、実モデルによるストリーム取得は未実施。

## Goals / Non-Goals

- 既存の10秒更新と工程境界の保存を使い、追加のモデル要約や常駐サービスを導入しない。
- 内部思考、機密を含み得るコマンド引数・ツール出力全文を利用者向け表示へ転記しない。
- 途中報告の無いモデルでも、工程・対象・観測できたツール種別を表示する。完了率や作業内容を推測しない。

## Decisions

### 1. stdoutを逐次保存し、表示用の情報だけ抽出する

Codex JSONL、Claudeのstream-jsonをpipeで受け、元の出力を試行ディレクトリへ保存する。UTF-8と行境界を保持して解析し、チャンク分割、未知イベント、末尾の未完行を許容する。ログ全体の反復読み取りは行わない。stderr、停止処理、終了コード、ファイルのcloseとバックプレッシャーを維持する。ログ保存失敗は技術的失敗とし、未知イベントは工程を失敗させない。

Claudeはstream-jsonと必要なverboseを使い、最終resultイベントを従来のclaude.jsonへ保存する。structured_output、session_id、modelUsage、usage、is_errorを従来処理へ渡し、性能計測・利用枠判定・セッション再開を維持する。Codexの最終応答は従来どおりresponse.jsonを使う。実CLIの確認は実装タスクの受け入れ条件とし、未検証の形式を完成扱いしない。

### 2. 活動と工程報告を分ける

進行中は試行開始時の工程・対象タスク・CLI・モデルを固定して保持する。activityには最新のエージェント報告、またはツール種別と開始／終了／失敗、受信時刻を記録する。本文の上限は500文字とし、切り詰めを明示して元ログへリンクする。内部推論イベントは抽出しない。最終JSONを途中報告として表示しない。

応答にはreportを追加し、scope（対象）、decisions（判断と理由の文字列配列）、verification（確認結果）、remaining（残件）を持たせる。両スキーマとpromptを更新する。新しい応答では対象を必須とし、判断がなければ空配列、未検証ならその旨を記す。reviewでは確認したファイル・受け入れ条件と結論を記す。既存の計画用decisionsは役割を変えず維持する。summaryだけへ全情報を詰める案は、表示と確認漏れの検証が難しいため採用しない。

### 3. 表示は試行に紐づけ、履歴は保存済み成果物を参照する

statusは現在の対象、担当、最新活動とその時刻、直近の工程報告と履歴リンクを返す。ダッシュボードの一覧には最新活動を短く載せ、詳細に現在の報告と試行別の工程・対象・成否・報告へのリンクを置く。モデル変更や差し戻し後も過去の担当・対象は変えない。新試行では活動を初期化し、過去の報告を現在の活動として扱わない。ハートビート時刻と活動時刻を区別し、「報告未取得」を表示する。

試行ごとのresult.json、invocation.json、metrics.jsonを履歴の出典にし、履歴全体をstateへ重複保存しない。失敗時に最終応答が無くても開始情報・最新活動・エラーとログを残す。旧履歴はsummaryを表示し、新項目の欠落を未記録とする。

## Risks / Trade-offs

- CLIのイベント形式差 → Codex実ログ由来とClaude実出力由来の縮約fixtureで検証し、未知イベントを無視する。
- 報告本文に機密が含まれる → 要求全文やツール出力を自動転記せず、保存先は既存のGit対象外dataとする。任意本文の完全な機密除去は保証しない。
- 報告が止まる → 最終活動時刻を示す。無報告を停止・失敗と自動判定しない。
- Markdown注入 → 既存のエスケープを適用し、本文をHTMLとして解釈しない。

## Migration Plan

旧state・ログは書き換えず読み取り互換とする。新しい試行から追加項目を使い、未記録値は明示する。実装時には既存の計測・再開・中断テストも通す。コードを戻しても元ログと従来の最終成果物を読める形を維持する。
