## ADDED Requirements

### Requirement: 実行前レビューでリポジトリの状態を読み取る
実行器は、実行前レビューの工程に、開発対象のファイルの読み取りに加えて、リポジトリの状態を読み取る読み取り専用のコマンド（Gitの作業ツリーの状態・差分・履歴・コミット内容の参照と、ディレクトリの一覧）の実行を許可しなければならない（MUST）。それ以外のコマンドと、対象changeのディレクトリ外への書き込みは許可してはならない。

#### Scenario: 作業ツリーの差分を確認する
- **WHEN** 実行前レビューがchangeと現在のコードを照合するために作業ツリーの状態と差分を参照する
- **THEN** そのコマンドは拒否されずに実行され、結果をレビューの根拠に使える

#### Scenario: 状態を変えるコマンドを実行しようとする
- **WHEN** 実行前レビューがコミット・チェックアウト・ファイル削除など、リポジトリの状態を変えるコマンドを実行しようとする
- **THEN** そのコマンドは許可されない

### Requirement: 権限要求の許可が実効であることを確認する
実行器は、権限要求に対してパスを許可するとき、次の実装工程と同じ実行条件でそのパスを読み取れるかをモデルを呼ばずに確認しなければならない（MUST）。読み取れないパスがある場合は、許可を保存せず、エージェントへ回答を送らず、待機状態を保ったまま、読み取れないパスとOSのアクセス権が原因であることを返す。確認は有限のタイムアウトで行い、対象の内容を保存しない。

#### Scenario: 許可したパスを読み取れる
- **WHEN** 許可するパスが実装工程の実行条件で読み取れる
- **THEN** 許可を保存し、許可した内容を回答として同じセッションへ伝えて再開できる状態にする

#### Scenario: OSのアクセス権で読み取れない
- **WHEN** 許可するパスが実装工程の実行条件で読み取りを拒否される
- **THEN** 許可は保存されず、状態はwaitingのままで、読み取れないパスとOSのアクセス権の修正が必要であることが返される

#### Scenario: アクセス権の修正後に許可し直す
- **WHEN** 読み取れなかったパスのアクセス権が修正された後で、同じパスを許可する
- **THEN** 確認に合格し、許可を保存して再開できる状態にする
