# 要求仕様

Workflow Executorの要求仕様を記述する。

## ワークフロー実行
以下のワークフローを実行する。

1. 入力された要求をタスクに落とし込む(openspecを作成するので良い)
2. タスクの粒度が適切かどうか判断し、必要なら細分化する
3. ソフトウェアアーキテクチャの観点からタスクが適切かどうか判断し、必要ならタスクを再定義する
4. タスクを実行する
5. 実行結果をレビューする。必要ならタスクの再定義に戻る。
6. 実行結果がそろったら、人に通知する

- タスクの実行やレビューはそれぞれ新しいコンテキストのエージェントで実行する

## ワークフロー実行状態
普段の実行状態は、skillを呼び出したチャットで確認できればよい。

将来、多数のワークフローを並列実行する際は、定期的に状態を把握してダッシュボードを更新する。クライアントが全体の状況と、自分が優先して対応すべきワークフローを判断できることを目的とする。各ワークフローについて、クライアントの対応が必要か、必要な回答・判断・成果確認の内容、対応しない場合に何が待ち状態になるかを示す。表示形式と優先順位の判断基準は、クライアントによる使い方の評価を通じて決める。

## ファイル
Workflow Executorに関するデータは、このディレクトリ内に保存する。開発用の作業ディレクトリには保存しない。

## 使い方
- 普段の開発で利用するCodex DesktopやClaude Codeのデスクトップアプリのチャットを入口とする。
- skillが提供され、人はskillを呼び出すだけで使用できれば良い。
- ワークフローを実行するエージェントからの質問は、skillを呼び出したチャットで普通の文章で回答したい。

## 非機能要件

- トークン消費量は削減する

## 将来の展望
- codexとclaudeの両方を活用する
- それぞれのタスクに最適なモデルと推論レベルを選択する
- それぞれの作業の実行結果や作業の効率さ、トークンの効率さを評価し、将来のタスク実行におけるモデルや推論レベルを最適化するデータを蓄積する
- 複数ワークフローを管理し、並列実行できる
